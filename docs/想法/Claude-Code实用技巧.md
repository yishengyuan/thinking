# Claude Code 实用技巧(实用版)

> 一份「能直接上手」的 Claude Code 使用技巧整理,按"最值钱"往下排。
> 命令/快捷键可能随版本微调,以 `/help` 实际显示为准。

---

## 一、上下文管理(最值钱,先学这个)

Claude Code 的能力高度依赖"上下文里有什么"。管好它,效果立刻不一样。

| 命令 | 作用 |
|------|------|
| `/context` | 看当前上下文用量(占了多少) |
| `/compact [重点]` | **主动压缩**,可带重点:`/compact 保留API改动和测试方案` |
| `/clear` | 清空、开新会话(换任务时用,别让旧上下文干扰) |

- **auto-compact 是按"用量"触发的,不是按时间**(快到上限自动压);**没有"8 点定时压缩"这种钟点触发**。
- 压缩时:**先丢旧的工具输出(读文件内容、bash 输出、搜索结果),不够再摘要对话**。
  保留你的诉求/关键决策/代码;`CLAUDE.md` 会重新注入。
- 推论:**重要结论别只躺在工具输出里 —— 落到对话结论或文件中,压缩后才不丢。**
- 大调研/大搜索**丢给子代理**(见第五节),结论回主线,保持主上下文干净。


## 二、四个输入符号(高频)

| 符号 | 用途 | 例子 |
|------|------|------|
| `/` | 斜杠命令 / 技能 | `/review`、`/compact` |
| `@` | 引用文件/目录进上下文 | `@src/main.go 看下这里` |
| `!` | 直接跑 bash,输出进上下文 | `!git status` |
| `#` | 快速写入记忆(CLAUDE.md) | `# 这个项目用 pnpm 不用 npm` |

---

## 三、记忆:CLAUDE.md

- **项目级** `./CLAUDE.md`:项目约定、常用命令、代码规范、给 Claude 的提示 —— 会自动加载。
- **用户级** `~/.claude/CLAUDE.md`:你跨项目的个人偏好。
- `/init` 自动生成一份;`/memory` 编辑;`#` 开头一句话快速追加。
- 心法:**反复要解释的东西,写进 CLAUDE.md 一次,省掉以后每次重复。**

---

## 四、计划模式 & 模式切换

- **Shift+Tab** 循环切换模式:普通 → 自动接受编辑(auto-accept)→ **计划模式(Plan Mode)**。
- **计划模式**:让它**先调研+给方案、不动手**,你确认后再执行 —— 复杂/有风险的改动强烈建议先 plan。
- 简单重复的批量改动可切 auto-accept 提速。

---

## 五、子代理 & 并行

- 把**大搜索、跨多文件的调研、独立子任务**交给子代理(subagent / Task),
  它在**独立上下文**里干活,只把结论带回来 —— **不污染主上下文**。
- 多个**互相独立**的任务可以并行跑。
- `/agents` 管理子代理配置。

---

## 六、会话恢复 & 回退

| 操作 | 作用 |
|------|------|
| `claude -c` / `--continue` | 继续最近一次会话 |
| `claude -r` / `--resume`、`/resume` | 选一个历史会话恢复 |
| **Esc** | 打断当前生成 |
| **Esc Esc**(双击) | 回到之前的消息编辑/重来 |
| `/rewind` | 回退到之前的检查点(代码 + 会话) |

> `/rewind` 很救命:改崩了能退回干净状态,不用手动 git reset。

## 七、设置 / 权限 / Hooks

- **settings.json 三层**(优先级:本地 > 项目 > 用户):
  `~/.claude/settings.json`(用户) · `.claude/settings.json`(项目) · `.claude/settings.local.json`(本地,不提交)。
- **权限**:在 settings 里 allow/deny 工具或命令,减少反复确认(`/config` 可视化调)。
- **会话清理**:`cleanupPeriodDays`(默认 30 天)—— 想"一周没用就清本地会话记录"就设 `7`:
  ```json
  { "cleanupPeriodDays": 7 }
  ```
- **Hooks 是事件驱动**(不是定时):`SessionStart`、`UserPromptSubmit`、`PreToolUse`/`PostToolUse`、
  `PreCompact`、`Stop` 等 —— 可用来自动跑测试/格式化/校验。**没有 cron/钟点触发。**

---

## 八、自动化 / 脚本化(headless)

- `claude -p "你的指令"`:**非交互**模式,直接出结果 —— 可接 CI、脚本、cron。
- 配合权限白名单和 hooks,能做"提交前自动检查""定时跑某任务"等。

---

## 九、高效协作的习惯(心法)

1. **任务拆小 + 给明确验收标准**("跑通这个测试""接口返回 X")比"帮我搞一下"强得多。
2. **先让它读相关文件/代码再动手**(`@` 引用),别让它猜。
3. **复杂任务先 Plan Mode**,看方向对不对再执行。
4. **大调研丢子代理**,保持主上下文聚焦。
5. **结论落地到文件 / CLAUDE.md**,别只留在会话里(防压缩丢失)。
6. **频繁 git 提交**,配合 `/rewind`,试错成本极低。
7. **反复纠正同一件事 → 写进 CLAUDE.md**,一劳永逸。

---

## 十、Claude Code on the web 的额外注意

- 会话跑在**临时容器**里,空闲会被回收 —— **想留住的东西必须 commit & push**,否则容器一回收就没了。
- 出网受**网络策略**限制(创建环境时选定)。
- GitHub 操作走 MCP 工具,不是 `gh` CLI。

---

## 一句话总结

> **80% 的体验提升来自两件事:管好上下文(`/context`·`/compact`·子代理)+ 用好 CLAUDE.md(把重复说明沉淀下来)。**
> 其余命令是锦上添花,先把这两样吃透。
